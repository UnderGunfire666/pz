# 项目进展、功能清单与开发路线

> 盘点日期：2026-10-07  
> 项目：Afterlight：Orangeville  
> 参照：《Project Zomboid》式单机僵尸生存；首要开发重点为幸存者 NPC。

## 用途与盘点口径

本文是项目状态和计划建议的持续更新基线。后续更新应检查当前代码、资源、场景、测试、README 和计划文档，并更新日期。区分可运行实现、基础原型、数据/工具准备、待验证和缺失项。存在数据资源不代表玩法已完成；自动化测试通过也不等于完成了完整人工游玩验收。

状态定义：**已实现**表示有明确代码及可观察行为；**基础实现/部分实现**表示核心路径存在但范围或验证有限；**数据/工具已具备**表示有数据结构、资源或编辑工具，但不代表玩家玩法已完成；**缺失**表示尚无可确认的玩法实现。此清单不声称与 PZ 功能等价。开发避坑清单是风险检查材料，不是当前实现问题的证明。

## 项目概况

项目使用 Godot 4.7.2 与 GDScript，是单机第三人称生存原型。主场景为 scenes/main.tscn，地图资源为 resources/maps/orangeville_prototype.tres，64×64 逻辑格，含住宅、三层杂货店、道路、楼梯、室内物资和测试点。已有多楼层探索、搜刮、背包、战斗、生存状态、伤病、僵尸遭遇、一名简化幸存者 NPC、存档和地图编辑工具。

整体短板是玩法闭环和内容深度：没有完整任务目标、胜败结算和重开引导；NPC 还不是 PZ 式社交、队伍、职业分工或群体生存系统；地图环境仍以程序化占位内容为主。

## NPC 开发路线（建议）

先让单个 NPC 行为可靠、可解释、可复测，再扩展社交和群体。不要把关系字典、职业资源或攻击逻辑写成完整社交/职业系统。遵循 docs/PZ_DEVELOPMENT_PITFALLS.md 的相关护栏：模拟状态权威且与渲染分离；测代表性密集场景；存档迁移有覆盖；动态障碍能使导航缓存失效。

| 优先级 | 方向 | 目标与验收建议 |
|---|---|---|
| P0 | 单 NPC 生存闭环 | NPC 因缺水/饥饿寻找资源，权衡路径与威胁并使用资源；遇敌后撤离或反击，危险消除后恢复需求目标。覆盖暂停、跨层、受伤、目标消失、存读档。 |
| P0 | 行为可解释性 | 调试视图显示需求、目标、感知来源、记忆位置、路径和转换原因；日志能说明行为失败原因。 |
| P1 | 目标与资源决策 | 对喝水、吃饭、休息、搜刮、回家、避险等候选评分；资源不可达/消失或危险变化时取消重选，避免失败目标循环。 |
| P1 | 伤势和战术适配 | 身体部位、体力、武器和威胁数量影响决策；腿伤改变逃跑，手臂伤降低攻击意愿；避免盲目冲入多只僵尸。 |
| P1 | 玩家与 NPC 小队 | 支持跟随、停止、集合、撤退等少量命令；跨层跟随，不堵路；危险后恢复原命令。 |
| P2 | 信任、关系与社交 | 救援、交易、攻击、遗弃等事件改变关系；关系影响招募、分享、跟随、冲突和离队。 |
| P2 | 分工与群体生存 | 支持守卫、搜刮、治疗、搬运；工作可取消、失败、重派；角色动机和物资可追踪。 |
| P3 | 持久幸存者世界 | 小规模阵营、离线活动、据点迁移和世界事件；先确保单队性能、存档及长期模拟稳定。 |

### 建议的第一个 NPC 里程碑

让现有幸存者自主完成：**发现缺水 → 选择可达水源 → 搜寻并饮用 → 遭遇僵尸后撤离或反击 → 返回安全区域休息**。记录目标变化和失败原因，并覆盖跨层、受伤、目标失效、暂停及存读档。该闭环检验 NPC、导航、听觉、生存、容器和存档集成；通过后再加入玩家跟随命令与关系系统。

## 其他近期方向

1. **闭合一轮可玩流程。**从安全点搜集指定补给并返回，加入目标说明、成功/失败判定、结算和重开路径；让 NPC 是否协助实际改变玩家选择。
2. **完成人工行为验收。**对目标取消、威胁记忆、跨层、受伤、暂停和读档建立可重复场景。
3. **按测量优化。**近期计划记录导航邻接优化和远距离动画降频；压力样本不等于完整 AI 模拟。增加 NPC 数量前，测量遭遇场景帧时间、AI 更新和路径请求成本。
4. **按闭环需要扩内容。**社交、尸体搜刮、角色创建和更大地图按实际玩法价值排序，不以资源数量替代玩法完成度。
