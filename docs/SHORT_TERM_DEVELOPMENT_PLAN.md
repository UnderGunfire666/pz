# Afterlight 短期开发指导

本文是当前阶段的开发顺序与验收依据，优先级高于早期 MVP 蓝图中的“下一阶段”清单。计划聚焦两件事：先解决已有测量指出的性能风险，再把现有系统组织成一轮可开始、可完成、可重玩的生存体验。它不是长期内容承诺；每阶段应以可复现的测量和可试玩结果决定是否进入下一阶段。

## 当前基线

- 项目是 Godot 4.7.2 单机第三人称生存原型。当前 Orangeville 示例地图为 64×64 逻辑格，包含住宅、三层杂货店、道路、楼梯、室内物资和测试点。项目已有分层地图、搜刮、容器与背包、战斗、疲劳/饥饿/口渴、伤势、休息、NPC、僵尸、实时服装、存档及地图编辑器。
- 最近的完整启动测量中，整图导航构建约 1.7 秒，是已知的主要启动耗时。渲染按 16×16 地块分批构建，但地图和导航数据仍常驻；进入游戏或读档会同步准备附近地块。
- 64 个动画穿衣角色的合成压力场景约使用 968 MiB 显存、671 次 draw call。此数字不能直接代表典型游戏场景，应先测实际同时可见角色数量和目标硬件。
- 已有的导航、声音和渲染合成压力样本各自覆盖范围有限，不等同完整游戏帧或大地图模拟表现。先统一测试场景和指标，再对症优化。
- `docs/MVP_BLUEPRINT.md` 保留了多楼层设计决策，但其中的 18×14 地图描述及若干“尚未实现”条目已过时。当前状态以 README、运行代码和本文件为准。

## 阶段 0：建立可复测的性能基线

先准备并记录冷启动到可操作、读档到可操作、典型遭遇、密集遭遇、长物品列表操作等场景。每次记录机器/GPU、画质、分辨率、实体数量，以及 CPU/GPU 帧时间、启动分阶段耗时、显存/内存、draw call。分别测 16/32/64 个可见穿衣角色；路径、声音和背包测试要记录单次与同帧峰值。保留原始结果，避免将合成压力场景误当作实战数据。

**验收：**基准能在同一环境重复运行并比较；找出导航构建中最耗时的子步骤，以及典型角色数量下的实际瓶颈。暂不为尚未复现的风险重写系统。

### P0 基准入口

`tests/performance_baseline.tscn` 是本阶段的统一 CPU 与启动基准。它会重复启动完整场景，分别记录导航节点生成、邻接连接和楼梯接入，以及地图/导航和完整初始化耗时；随后用不覆盖正式快速存档的临时文件记录存读档时间，并采样实际地图寻路、128 名听者的声音扇出、256 件物品的背包重建和 120 帧空闲场景。每次运行在控制台输出一条可保存、可比较的 JSON 报告。

```text
godot --headless --path . res://tests/performance_baseline.tscn
godot --path . res://tests/performance_baseline.tscn
godot --path . res://scenes/characters/character_preview.tscn -- --benchmark
godot --path . res://tests/streaming_benchmark.tscn
```

无头运行用于启动、导航、声音和 UI 的 CPU 趋势；带真实图形后端的运行才记录有效的 GPU、draw call 和显存数据。服装预览仍单独覆盖 64 名穿衣动画角色，流送基准仍单独覆盖静态地块；报告中不将它们表述为完整 AI 或地图规模结论。每次对比都应附带机器、GPU、驱动、分辨率和命令行参数。

### 首个参考结果（2026-10-06）

使用 Godot 4.7.2、D3D12 Forward+、1280×720、NVIDIA RTX 4070 SUPER 和当前 64×64 Orangeville 地图运行上述场景。三次同进程完整场景初始化的中位数为 1831.47 ms，其中地图与导航为 1648.65 ms；导航节点生成 208.72 ms、邻接连接 1411.16 ms、楼梯接入 12.83 ms。邻接连接因此是 P1 的第一个已证实热点。

同次运行中，临时槽存读档中位数为 92.79 ms；128 次寻路请求中首次未命中缓存，后续 125 次命中，P95 为 0.004 ms；128 名听者、20 次声音事件的扇出中位数为 10.23 ms；256 件物品的背包完全重建中位数为 31.05 ms。空闲场景帧时间中位数为 6.06 ms、P95 为 8.00 ms，渲染 CPU P95 为 0.29 ms、GPU P95 为 5.89 ms，132 次 draw call、约 862 MiB 视频内存。背包完全重建是第二个需在 P1 中分析的热点。

这次运行因用户目录不可写而未创建 Godot shader cache；它不影响计时功能正确性，但首次启动数据不应作为带缓存的冷启动承诺。后续应在目标硬件、可写用户目录和相同命令行参数下复跑，并保留 JSON 输出供比较。

## 阶段 1：处理已证实的性能热点

1. **已完成：**拆解并减少整图同步导航构建成本。保留楼层／楼梯连通、动态门窗和家具后的局部图重建、不可达目标处理；后续只在测量证明收益时再考虑缓存、按需构建或分帧。
2. **已完成：**按实战可见角色数量优化角色资源成本。服装网格和材质已复用，远距离非玩家角色的动画求值按距离降频；模拟状态仍由权威游戏逻辑推进，渲染降级不改变感知、战斗或命中结果。
3. 对长物品列表、搜索/转移和反复开关背包测量帧时与内存趋势；如果测试发现扫描或 UI 重建成本，再采用可见行生成、缓存和状态驱动刷新。
4. 用实际游玩中的事件频率复测声音传播与寻路峰值。没有持续实战影响时，不将压力测试微优化排在垂直切片之前。

### P1.1 导航邻接构建（2026-10-06，已完成）

基线将 65,980 条候选边分项：支撑采样是主要成本，墙体净空查询为次要成本。完整图构建现在记录节点、邻接、楼梯、支撑采样、墙体净空、候选边和接通边的耗时，供之后的改动继续比较。

墙体与楼梯的空间索引增加了只供“是否存在碰撞”判断使用的候选查询。它跳过对重复候选的去重和排序；重复项不会改变碰撞结果。支撑检查也不再为同一位置先做零半径、再做角色半径的楼梯查询。公开的有序查询、精确线段净空、图节点端点验证、楼梯连接和动态障碍物局部重建保持原有规则。

在与 P0 参考结果相同的 Godot 4.7.2、D3D12 Forward+、1280×720、RTX 4070 SUPER 和 64×64 Orangeville 场景中，三次初始化中位数如下：

| 指标 | P0 | P1.1 | 变化 |
| --- | ---: | ---: | ---: |
| 导航邻接 | 1411.16 ms | 1093.23 ms | -22.5% |
| 地图与导航 | 1648.65 ms | 1292.99 ms | -21.6% |
| 完整启动 | 1831.47 ms | 1455.98 ms | -20.5% |

P1.1 的邻接阶段中位数里，支撑采样为 947.72 ms、墙体净空为 74.42 ms，接通 65,632／65,980 条候选边。当前完整无头回归通过 770 项检查，覆盖单次图构建签名、多楼层路径、楼梯、动态障碍局部重建、不可达路径节流及空间查询。支撑采样仍是下一项导航改动前必须重新测量的热点；本阶段不以降低采样密度交换通行语义。

### P1.2 角色展示资源与远距离动画（2026-10-06，已完成）

实际 Orangeville 基线通常渲染玩家、NPC 与 9 个僵尸，共约 11 名角色；它的空闲 P95 为 8.00 ms，135 次 draw call。64 名穿衣且播放动画的角色是用于显示上限趋势的独立压力场景，不代表完整地图、AI 或战斗规模。

检查确认服装网格按资源路径共享，且只在装备槽位 ID 变化时替换；每件衣物不创建额外动画播放器。新增的展示层策略只影响远距离、未攻击的僵尸和 NPC：8 米起以 30 Hz 求值骨骼姿势，14 米起以 15 Hz 求值；模型位置、朝向、服装装备状态、AI、寻路、战斗、命中和伤害仍按原有频率和权威模拟状态更新。攻击中的角色不降频。

同一 RTX 4070 SUPER、D3D12 Forward+、1280×720 环境下，64 名混合穿衣角色压力场景的帧时间中位数保持 6.07 ms，P95 从 10.48 ms 降至 7.13 ms；渲染 CPU P95 从 0.93 ms 降至 0.89 ms，draw call 保持 671，显存约 970 MiB。这证明该改动减少了姿势求值的尖峰，并未减少网格或贴图成本；降低 draw call、纹理尺寸或显存需要在目标美术规格确定后另行测量。完整无头回归通过 770 项检查，并新增了近、中、远距离动画频率门槛的覆盖。

**验收：**每项优化都有同一场景的前后数据；典型场景没有可感知卡顿；门窗、楼梯、存档和 NPC 行为回归正常。性能门槛应在确认目标机器后制定，不以未经测量的硬件数字作为承诺。

## 阶段 2：交付一轮可完成的生存玩法

以现有住所和杂货店路线为基础，制作一项具体、短而可重复的任务。例如：从安全住所出发，在有限时间或资源压力下搜集指定补给，再带回安全点。关卡布置要让玩家能选择搜刮、战斗或绕行，并让路线、楼层和物资支持这些选择。

一轮流程应包含：

1. 开始时说明目标和必要操作；使用当前默认角色，不先扩张职业/特质选择。
2. 离开安全点，探索并搜索容器，决定携带什么以及是否继续深入。
3. 遇到威胁时可战斗或脱离；负重、疲劳、伤势和噪声会影响后续选择。
4. 返回安全点，使用现有的存放、治疗和休息能力处理所得与代价。
5. 达成目标或明确失败后显示结果，保留合理的存档/重开路径。

优先补任务状态、必要的目标提示/线索、成功与失败判定、结算和重新开始。只新增闭合这一轮所必需的交互；NPC、尸体搜刮和其他角色换装界面按是否能实质改变本轮决策来决定范围。

**验收：**未看开发文档的玩家能理解目标；可以完整走通成功与失败路径；结果有明确反馈；关键角色、容器、任务和世界状态经过保存/读取仍一致；同一路线至少能提供两种有意义的应对方式。

## 阶段 3：打磨与扩展门槛

先修复试玩中阻断流程的问题，校准物资、威胁和提示，再验证多次开局、死亡重开、存档继续和长时间运行。检查存档版本化迁移与原存档保留。达到可重复游玩且性能基线稳定后，再考虑更丰富的角色创建、尸体搜刮、内容扩展和更大地图。

### 后续：扩展食物、医疗与背包物品

扩充食物、医疗用品和可背负容器的物品目录，并为同类物品的状态变化保留一致的物品定义与独立状态属性。优先沿用项目现有的饥饿/口渴恢复、伤口治疗、背包容量及负重减免规则；物品名称可参考 PZwiki，wiki 不作为覆盖现有玩法数值和行为的依据。新增效果须先确认后实现。

食品可记录卡路里属性。后续角色体重系统按每日卡路里结余结算：结余为正则体重增加，为负则体重降低。体重系统与卡路里结算暂不属于本轮物品扩展实现范围，另行规划与实现。

食物具有温度属性，温度越高变质越快。冰箱可包含冷藏区和/或冷冻区；冷冻可进一步减缓变质，冷冻食物取出后需缓慢解冻，室温和冷藏区都能解冻，但各自有不同的最高温度。冷饮类食物不要求解冻。靠近热源会加快解冻。

冷藏区目标温度为 4°C，冷冻区为 −18°C。

变质速度按物品当前温度换算，以 20°C 下该物品的常温保存期限为基准；温度每降低 10°C，变质速度减半（乘数为 `2^((温度°C−20)/10)`）。

食物温度向周围温度缓慢变化：环境温度为 0°C 时，每游戏小时变化 1°C；环境每高于 0°C 1°C，变化效率增加 2%；每低于 0°C 1°C，变化效率减少 2%（例如 30°C 环境下为 1.6°C/游戏小时）。食物温度高于环境时按同一速率降温，低于环境时按同一速率升温，直至接近环境温度。冷藏区环境为 4°C，冷冻区环境为 −18°C。

冷冻食品的温度高于 0°C 后即可食用；温度为 0°C 或更低时仍视为未解冻。冰淇淋、冰棍等冷冻甜品可在冰冻状态下食用；罐装水、瓶装水、果汁等饮用液体在冰冻状态下不能饮用，解冻后即可饮用。

食物新鲜度在其参考保质期内从 100 线性下降到 0；温度导致的变质速度倍率同步调整新鲜度下降速度。

首批食物目录包括：生鲜（鸡蛋、牛奶、鸡肉、牛肉、鱼、苹果、浆果、胡萝卜、土豆、卷心菜、番茄）；罐头（豆类、玉米、金枪鱼、沙丁鱼、番茄、蔬菜汤、水果拼盘）；口粮（应急口粮）；零食（薯片、饼干、燕麦棒、巧克力、冰淇淋、冰棍）。

肉类、鱼类、鸡蛋、土豆、口粮、蔬菜和水果需要记录烹饪状态；烹饪机制暂不实装，留待后续与炊具系统一并实现。烹饪状态为生、熟、烧焦。水果处于生的状态时即可食用。
应急口粮默认处于熟的状态，可直接食用。
罐头食品也记录生、熟、烧焦状态，处于生的状态时即可食用。

首批目录额外包含可饮用液体：罐装水、瓶装水和果汁。液体冻结时不可饮用，解冻后可以饮用。

液体单件容量：罐装水 355 mL、瓶装水 500 mL、果汁 250 mL。

液体可分多次饮用，保留未饮用的剩余量；饮尽后留下对应的空罐、空瓶或空包装。

空瓶和空罐可重新装水；果汁饮尽后留下空包装。

水未开封或开封后均不会变质。未开封果汁不会变质；开封果汁使用 7 天的参考保质期（20°C），并按食物温度调整变质速度。

饮用为持续动作，不提供固定单次饮用量选择。按正常成年人每游戏分钟饮用 100 mL 计算；时间换算示例为现实 1 秒 = 游戏 1 分钟，因此现实饮用 1 秒消耗 100 mL。吃东西等动作也按现实中的常见行为速度换算游戏内消耗量。
饮用动作在口渴值恢复满或容器喝空时自动停止，玩家可手动中断。
进食动作在饥饿值恢复满或食物吃完时自动停止，玩家可手动中断。
每种食物的进食速度按正常成年人吃完该份量或包装的常见现实时间分别设置，食物会随动作持续时间逐步消耗。

每件食物的卡路里按现实中一个常见单份的热量（kcal）设置，不统一折算为每 100 克。
鸡肉、牛肉和鱼肉每件按 100 克一份设置。
鱼肉热量以 100 克鳕鱼作为通用代表值。
水果和蔬菜按常见可食用单位作为每件份量（如一个中等苹果、一根胡萝卜、一个土豆、一小把浆果）。
罐头、口粮和包装零食每件按一个常见完整包装作为份量。
未开封应急口粮和包装零食暂时不会变质；开封后使用 30 天的参考保质期（20°C），并按食物温度调整变质速度。

新增生鲜、罐头和口粮默认不恢复心情；零食和甜品设置正向心情恢复值，具体数值后续按项目现有数值尺度确定。食物不新鲜时，心情恢复减半。

新生成的食物初始温度取其所在环境温度；例如在普通环境生成时取该处环境温度，在冷藏区取 4°C，在冷冻区取 −18°C。

食物存放在玩家背包中时，仍按玩家当前位置的环境温度逐渐升降温；随玩家进入不同环境，食物温度逐步向新的环境温度靠近。
所有普通地块（室内和室外）共用同一月份环境温度基准；冰箱、冰柜和未来的热源系统可单独改变局部温度。

本阶段的冰箱和冰柜始终正常工作，分别维持 4°C 和 −18°C，不模拟断电导致的温度变化。

密封罐头不变质；开封后罐内食品统一使用 30 天的参考保质期（20°C），之后按食物温度规则调整变质速度。

默认室外环境温度按安大略省 Orangeville 的月日平均气温设置，采用加拿大环境与气候变化部 1981–2010 气候常值，并在月份之间平滑渐变：1月 −7.5°C、2月 −6.5°C、3月 −2.1°C、4月 5.3°C、5月 11.7°C、6月 16.9°C、7月 19.4°C、8月 18.4°C、9月 14.3°C、10月 7.8°C、11月 2.0°C、12月 −4.1°C。对应的气象季节平均约为春季 5°C、夏季 18°C、秋季 8°C、冬季 −6°C。热源系统实现后可改变附近范围内的环境温度。

每件易腐食物记录 0–100 的新鲜度：50 及以上为新鲜，低于 50 且高于 0 为不新鲜，到达 0 时变为腐烂。新鲜度与温度等状态属于物品实例数据；相同定义的物品可以因实例状态不同而表现不同。

腐烂食物禁止食用。

不新鲜食物仍可食用，饥饿、口渴和卡路里效果保持原值，心情恢复效果减半。

密封罐头不变质；开封后剩余内容开始按对应食物的保存期限变质。

开罐需要手持开罐器或匕首。开罐器是可重复使用的手持装备，不会因开罐而消耗；匕首也可用于开罐。

工具仅在作为武器使用时损耗耐久；开罐、拆桌椅等工具用途不损耗耐久。此规则适用于螺丝刀、锤子、开罐器和匕首等工具。

工具目录和用途仍需确认；医疗物品首批范围待确认。

医疗物品按 PZwiki Medical 的类别纳入绷带、消毒剂、药品、医疗工具和其他医疗物品；不纳入敷料、草药和包装类物品。具体新增药品效果以项目现有角色状态为基础，新增效果另行确认。

医疗工具支持深层伤口和体内异物处理，并将深层伤口、异物及其状态纳入权威伤口模型和存档；首批异物包括玻璃碎片和子弹，玻璃用镊子取出，子弹需止血钳配合镊子取出，使用正确工具时取出必定成功。所有去除异物后的伤口都会变成需要缝合的伤口；缝合针可用于缝合，止血钳不参与缝合。

异物仍留在体内时，即使伤口已止血或包扎，也不能开始愈合。

本轮伤口模型支持子弹异物状态，但暂不加入枪械或子弹伤害来源。

抗抑郁药每剂在 8 个游戏小时内降低 20 点不快乐值。

β 受体阻滞剂持续 8 个游戏小时，将新增加的恐慌减半，并将恐慌上限降至 50；服药时若现有恐慌高于 50 则保留原值，只阻止其继续升到 50 以上。压力为 0 时，恐慌自然消退速度由每游戏小时 35 点加倍到 70 点。效果期间再次服用只刷新 8 小时持续时间，不叠加强度。

疲劳值采用 0 表示充分休息、数值越高越疲劳的刻度。每片咖啡因药片立即降低 40 点疲劳，并在生效期内减缓疲劳累积；药效持续 4 个游戏小时，静止时累积速度由每游戏小时 1.5 点减半为 0.75 点。药效结束后触发持续 3 个游戏日的咖啡因崩溃，使疲劳累积加快；基础疲劳和运动额外疲劳的累积速度均加倍，静止时为每游戏小时 3 点。崩溃期间服用咖啡因药片的效果减半；一次充分睡眠（疲劳降至 0）会清除崩溃造成的疲劳加速效果，但不清除崩溃期，也不恢复药片效果。当前代码中的 `survival.fatigue` 使用相反方向的疲劳储备刻度，后续实现时需调整状态表示并兼容存档。

咖啡因药效期间重复服用不延长药效或叠加强度，而会触发“咖啡因中毒”，暂含恶心和焦虑两种异常状态。恶心、焦虑属于玩家异常状态而非特质；其具体数值效果另行规划。

“安眠药”先服用并获得持续 8 个游戏小时的 buff；药效期间可以绕过疲倦不足，以及疼痛、焦虑达到 60（暂定测试阈值）及以上的睡眠限制，但附近有危险时仍不能睡。若 buff 在睡眠期间结束，疼痛或焦虑仍达到阈值会使角色疼醒或因焦虑做噩梦惊醒，打断睡眠。药效期间再次服用不刷新时间且不提供正面效果，而会触发“安眠药过量”异常状态，包括呼吸变弱（气喘吁吁效果）、眩晕、部位系统中的四肢肌无力，以及肌肉酸痛 debuff。眩晕、肌无力、肌肉酸痛等异常状态的具体数值影响另行规划。

常温保存期限先以肉类、鱼类和海鲜 2 个游戏日，蔬菜和水果 5 个游戏日作为默认值；鸡蛋为 10 天，牛奶为 5 天。物品定义保留单独设置保存期限的能力，后续可按具体食物覆盖默认值。

背包物品目录覆盖 PZwiki Container 的 Wearable / Back 全部条目，并移除项目原有的原型背包物品；颜色和款式变体作为同一背包的外观属性处理，不另建物品。既有背包容量、穿戴和负重减免玩法保持现行实现。

食物目录选择一批常见的生鲜、罐头、口粮和零食，不照搬 Food 页的全部条目；具体首批清单待确认。

绷带用于包扎后会吸收血液并逐渐变脏，变脏速度取决于包扎时记录的原始伤口出血量；以当前出血值作为每游戏小时的吸血速度，累计吸血值达到 28 时变脏。吸血量大于 0 但未满时显示为染血绷带，名称用于提示，实际效果与普通绷带相同；达到 28 后显示为脏绷带，并切换到脏绷带的持续感染效果。

更换伤口上的绷带时，先卸下旧绷带并保留其吸血量，再立即绑上新绷带。绷带可以用水清洗以清零吸血量；清洗需要消耗水，且清洗时间和用水量都与吸血量成正比。清洗会去掉绷带的消毒状态，使其恢复为普通干净绷带。普通、消毒和脏绷带的持续感染效果按伤口上当前绷带状态生效。

玩家可用现有消毒剂给普通干净绷带消毒；操作沿用现有医疗用品的一次性消耗规则。有吸血量的染血绷带须先用水洗净，才能再次消毒。

后续热源系统设想：地块默认室温随季节变化，并在季节对应范围内波动；热源可改变附近一定范围内的室温，进而影响食物温度、变质和解冻。当前项目尚未实现热源，此温度模拟设想只记入计划，暂不实现。

## 开发护栏

- 模拟状态是权威来源；渲染、动画和 HUD 读取状态并发出明确命令，不反向决定玩法结果。
- 新增动态障碍时明确哪些导航/可见性缓存失效；楼层和楼梯规则必须由世界地图数据决定。
- 存档字段变更需版本化、可重复迁移，并验证失败时原存档仍可用。
- 每阶段围绕代表性密集场景和完整游玩组合验证；自动化检查之后仍需人工走通垂直切片。
