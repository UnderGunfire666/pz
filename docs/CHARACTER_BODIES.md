# 角色模型与部位受击

`assets/characters/mixamo/Human/Player.fbx` 和 `assets/characters/mixamo/Zombie/Zombie.fbx` 使用用户提供的 Mixamo 模型。玩家与 NPC 共用 Human 网格、骨骼和动作；渲染入口是 `World3DView._create_actor_visual()`，导入网格、骨骼姿态、动作和受击闪光由 `MixamoCharacterVisual` 管理。网格和原始材质共享，闪光用材质叠加，不覆盖原贴图。

## 查看模型

在 Godot 打开 `scenes/characters/character_preview.tscn`，按 F6。B 显示/隐藏校准姿态的身体判定框，鼠标点击显示第一个命中的部位。主游戏第三人称显示玩家完整身体、头颈、腿脚和骨骼双臂；独立预览也显示完整源模型。

Human 动作集包含 `idle`、`walking`、`running`、`Walking Backwards`、`Run Backward`、左右横移、`2hand Idle`、`Run With Sword`、`Attack Downward` 和 `Unarmed Equip Underarm`；玩家与 NPC 共用该动作集。玩家使用两个骨骼动画层：下层只写骨盆和腿脚，按实际移动播放走、跑、倒走、倒跑或横移；上层只写躯干、头部和手臂。按住右键进入预备状态，禁止冲刺且上层保持 `2hand Idle`；攻击时上层完整重启 `Attack Downward`，下层持续使用当前移动动作。僵尸使用 `zombie idle`、`zombie walk`、`zombie run`、`zombie attack` 和 `zombie death`；僵尸会先以有限角速度转向，在攻击站位停止移动。攻击动画进行到 46% 时打开单次权威碰撞窗口，Human 动画总长为 2.2667 秒、僵尸为 2.6333 秒；攻击窗口内首次接触的实际身体部位立刻承伤，受击者取消尚未完成的攻击。画面是否渲染不会决定命中。跳跃尚未接入，因为当前模拟没有跳跃；僵尸死亡后依旧按现有规则移除，死亡动作留给尸体系统接入。根骨骼的位置轨道被禁用，地图位置和命中规则仍由模拟系统决定。手持物直接锚定上层动画手腕。没有布娃娃、肢解、全身换装或逐三角形命中。旧方块双手和程序化夹克不再生成，服装防护仍有效，但袖口、手套、外套等需要匹配新骨架的换装资产。

第三人称使用完整本地模型，保留头颈网格、骨骼、材质和完整头部受击区。`PlayerViewRig` 保持权威瞄准原点在玩家眼高，并将渲染镜头放在右肩后方；地图的空间视线检测会缩短镜头距离，避免其穿过墙体、楼板和屋顶。渲染镜头位置不会参与瞄准、身体受击或游戏规则。

## 命中与健康

- `resources/bodies/player.tres` 和 `zombie.tres` 保存统一到 1.8 米、脚底原点、前向 -Z 的模型变换和十个部位框。左右以角色自身为准。
- `ActorBody` 将这些框按模拟角色的朝向、位置和楼梯高度变换。玩家双臂与手框由 `PlayerBodyPose` 的权威关节点更新，每条手臂分成两个框，避免弯肘时出现过大的空隙判定。判定不读取渲染实例或动画，因此完整第三人称动作、隐藏、卸载与无图形运行都不会改变结果。
- `ActorCombat.contact()` 优先取瞄准射线上的最近部位；未直接命中时沿用原有近战角度容差，但重新检查身体表面及墙、家具、楼板遮挡，返回部位、世界命中点、距离和对准程度。玩家始终启用这些体积，僵尸和 NPC 仅在同层、同一楼梯状态且距离玩家三格内启用，减少远处角色的近战查询。默认球棒的挥击体积为一个沿权威攻击方向采样的细圆柱近似体，独立于 `batclean_low.glb` 的渲染模型。
- 玩家被攻击时，`ActorCombat.contact()` 的实际接触部位交给 `PlayerState.receive_hit()`，继续进行该部位的衣物防护、耐久损耗、伤口、感染、疼痛和治疗，并短暂闪红。腿脚伤降低移动速度，手臂和手伤降低攻击表现，头伤降低感知，躯干伤降低行动效率和耐力恢复。C 打开原有部位健康面板查看。
- 玩家、僵尸与 NPC 受击后，会在模型上短暂显示对应部位的红色调试覆盖盒；这只显示已经由模拟命中的部位，不参与伤害或碰撞判定。
- 僵尸部位生命值为 0–100；每点原型攻击伤害造成 50 点该部位损伤，头部对总生命值造成双倍伤害。最严重的腿/脚伤按比例将速度降低至最低 50%，臂/手伤将攻击伤害降低至最低 50%。僵尸总生命值仍为 2，肢体受击也扣总生命，不是独立的断肢/致残模拟。
- 新存档版本为 v11，记录僵尸和 NPC 的部位生命值。读取缺少 NPC 部位字段的旧档时设为健康；读取 v10 或更旧档案时保留僵尸总生命，未知的历史部位设为健康，不猜测受伤部位。迁移发生在副本中，旧文件不被覆盖。

## 更换模型后

导入新 FBX 后，用项目的 Godot 可执行文件运行：

```text
godot --headless --path . --script tools/bake_character_bodies.gd
```

该工具识别不同的 Mixamo 骨骼名前缀，应用与运行时相同的垂臂姿态，重新生成两个身体资源。随后检查预览中的身高、朝向、脚底和框的位置。框是根据骨骼生成的粗略人体体积，不是皮肤网格的精确包围体；体型差异很大的新模型需调整烘焙工具中的半径和躯干宽度。新增动作时，在 `MixamoCharacterVisual` 的动作表中登记资源路径；运行时会按骨骼名称后缀重定向轨道。新的权威攻击或移动规则仍须单独接入，不能让碰撞跟随可见动画。

## 验证与性能

`tests/body_part_tests.gd` 集成到现有 MVP 回归场景，覆盖两个身体的十部位/四朝向、真实僵尸攻击接入玩家伤口、衣物防护、僵尸肢体减益、存档恢复、无效数值拒绝和 v10 文件迁移。原有测试继续覆盖墙体、楼板、楼梯与方向限制。

全身替换后 MVP 回归通过 760 项检查，新增本地头部裁剪隔离、俯仰/朝向/攻击组合下手腕与持物对齐，以及摄像机原点一致性验证。另进行了持物、挥击和低头的实际渲染截图检查。

全身版本额外测量了 120 次玩家姿态与持物更新：CPU 中位数 0.107 ms、p95 0.127 ms（当前机器、已有地图、持锤静止姿态；不含完整帧的渲染成本）。骨骼索引和本地去头网格只在首次使用时建立缓存。

首次模型接入时运行过包含实际地图和居民模型的 streaming benchmark：密集街区静止样本帧时间 p95 约 7.91 ms、渲染 CPU p95 0.14 ms、GPU p95 3.28 ms、51 次 draw call。该基准冻结了模拟，用于检查当时的渲染集成，不代表完整 AI 压测或新增双臂逐帧姿态求解的成本。

可运行独立模型密集场景：

```text
godot --path . res://scenes/characters/character_preview.tscn -- --benchmark
```

本次 RTX 4070 SUPER、D3D12 Forward+、1100×720 的 64 个静态僵尸实例测得：帧耗时中位数约 6.06 ms，p95 约 6.16 ms，渲染 CPU p95 0.18 ms、GPU p95 1.91 ms、130 次 draw call、约 573 MiB 视频内存。该场景不包含 AI、完整地图或动画开销，且帧时间受垂直同步影响，不能当作完整游戏性能结论。原始僵尸纹理较大，后续批量美术资产应控制分辨率、显存与骨骼更新成本。
