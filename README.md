# Afterlight：Orangeville

Afterlight 是一款以《Project Zomboid》为参考的单机第三人称僵尸生存游戏原型，使用 Godot 4.7.2 和 GDScript。玩家与僵尸使用导入的 Mixamo 骨骼模型，环境与 NPC 仍以程序化占位模型为主。当前版本的重点是验证多楼层探索、视线遮挡、生存状态、物品操作与僵尸遭遇组成的核心循环；它还不是内容完整或美术定稿的游戏。

## 当前版本

- 主场景为 `scenes/main.tscn`，地图资源为 `resources/maps/orangeville_prototype.tres`。示例 Orangeville 地图采用 64×64 逻辑格，包含住宅、三层杂货店、道路、楼梯、室内物资和测试点。
- 世界默认采用右肩第三人称透视摄像机：权威观察原点固定在玩家眼高 1.62，镜头位于其后方 3.6 米，鼠标水平 360° 转向、上下观察限制在 ±85°。`PlayerViewRig` 用地图墙体、楼板和屋顶的空间视线检测将镜头拉近，避免穿入世界几何；镜头位置不会影响移动、近战、交互、AI 感知或命中判定。
- 可在一至三层间探索。玩家、僵尸和 NPC 共用楼层与楼梯通行规则；楼梯移动具有连续高度，途中可以停下和反向。
- 新游戏直接使用默认角色开始。角色创建面板暂时隐藏，待完整角色创建流程制作后再启用。
- 玩家和 NPC 共用 `assets/characters/mixamo/Human/Player.fbx` 及同一套 Human 动作，僵尸使用 `assets/characters/mixamo/Zombie/Zombie.fbx`；统一身高 1.8 米、脚底原点与前向。新玩家默认双手持有 `assets/RandomObjects/bat/batclean_low.glb` 的球棒。玩家未按右键时始终播放一套完整的人体待机、走、跑、倒走、倒跑或横移动画；按住右键立即进入预备状态，不能冲刺，此时才将上下身拆分：下半身继续按实际移动播放，上半身固定为 `2hand Idle`，攻击时上半身以 2 倍速播放 `Attack Downward`。松开右键会立即停止分层覆盖并回到完整动画；只有预备状态下左键才能攻击。NPC 也播放对应的人类待机、移动和攻击动作。攻击动画约进行至 46% 时打开一次权威命中窗口，命中由目标实际部位碰撞箱和遮挡决定；球棒还使用独立的圆柱近似挥击体积。球棒实际命中时播放短促打击声、镜头轻震，并使存活目标沿受击方向退让；挥空没有这些反馈。玩家攻击历时 1.1333 秒，NPC Human 为 2.2667 秒，僵尸为 2.6333 秒。攻击中和背向移动时速度显著降低。手持物直接跟随上半身动画手腕。Mixamo 根位移不会改变权威地图坐标。僵尸命中由身体部位盒确定，衣物防护后的伤口会降低对应部位健康：腿脚影响移动，手臂和手影响攻击，头部影响感知，躯干影响行动与耐力恢复。尚无完整可动画换装网格，衣物防护仍按装备状态生效。
- 近战按头、躯干、左右臂、手、腿、脚十个部位判定，结果接入原有玩家衣物防护、伤口、部位健康、治疗和状态面板。僵尸也记录部位健康：头部伤害为普通伤害的两倍，腿/脚损伤降低移动速度，臂/手损伤降低攻击伤害；总生命值仍沿用原型的 2 点平衡。
- 身体判定使用从模型校准姿态烘焙的简化部位框，随模拟位置、朝向和楼梯高度变换，玩家手臂和手部框随同一套权威姿态更新，不依赖模型是否可见。玩家及其三格内的僵尸和 NPC 参与近战碰撞查询；受到命中会取消尚未完成的攻击动作，并短暂以红色覆盖盒标识实际受击部位。打开 `scenes/characters/character_preview.tscn` 按 F6 可查看两个模型，B 切换判定框，点击显示部位；详见 [角色模型与受击系统](docs/CHARACTER_BODIES.md)。
- 已移除方块双手与独立外套代理，手持物暂用原有占位几何并绑定到玩家手腕。近战与 E 键交互根据包含俯仰角的权威观察方向选择目标；准星绿色表示可交互，琥珀色表示当前不可操作，提示说明原因。

## 启动

用 Godot 4.7.2 打开项目目录，按 F5 运行主项目；在编辑器内运行当前场景可用 F6。也可在安装了 Flatpak 版 Godot 的 Linux 环境运行：

```bash
flatpak run org.godotengine.Godot --path .
```

启动日志会输出地图/寻路、角色数据、交互、僵尸与 NPC、3D 世界、HUD，以及首次游戏更新的阶段耗时。耗时取决于机器、渲染驱动和运行方式；目前地图寻路构建是启动耗时需要继续关注的部分。

| 输入 | 操作 |
| --- | --- |
| WASD | 相对观察方向前后移动、左右横移；横移和后退不改变朝向 |

| 鼠标右键按住 | 进入预备状态：朝向跟随鼠标观察方向，不能冲刺，上半身保持双手预备姿态 |
| 鼠标左键 | 仅在按住右键预备时攻击；无武器时推击，持有可切换设备时可切换开关 |
| 鼠标移动 | 直接观察并同步玩家水平朝向 |
| Esc / 点击场景 | 关闭面板或释放鼠标并中断动作；点击场景恢复观察，该次点击不会攻击 |
| 鼠标滚轮 | 面板滚动；摄像机不缩放 |
| 沿楼梯方向移动 | 上下楼；楼梯途中可停下或反向 |
| E | 操作准星指向的门窗、容器或床；未搜索容器先耗时搜索，完成后打开物品栏，已搜索容器可直接开关；床开始休息/睡眠；打开的门窗可瞄准原开口关闭 |
| F / V / R | 吃 / 喝 / 整理背包 |
| 移动、瞄准、攻击、Esc、受伤 | 中断当前动作；未完成的搜索进度保留 |
| Space / `1` / `2` | 暂停 / 正常速度 / 3 倍速；也可使用 HUD 时间按钮 |
| Tab / Inventory | 打开或关闭物品栏 |
| C / Character | 打开人物状态面板 |
| Help | 打开操作帮助 |
| F5 / F9 | 快速保存 / 读档（读档后暂停） |
| 死亡后 Enter | 开始新一局 |

## 已实现功能

### 3D AI 感知与寻路

- 僵尸与 NPC 共用眼高、朝向和连续高度视线检测，检查墙体、楼板、屋顶与楼梯踏步，不依赖摄像机或渲染块。NPC 具有短时威胁记忆，模型朝向同步感知方向。
- 多楼层路径简化保留楼梯出入口，检查角色净空；移动目标限频重规划，受阻后延迟重试。NPC 逃跑评估可达安全方向，搜寻物资按路径长度评分。
- AI 只有在路线要求跨层时才进入指定楼梯，经过楼梯口的同层路线不会被吸入。连续受阻会切换到保守网格路径；楼梯出口封堵时退向另一端，门关闭时与 AI 重叠则先移回附近合法位置。最多缓存 64 条相同起终点路线，门窗／几何变化使缓存失效。
- 楼梯中途的目标按实际目击位置追踪，支持同梯折返及经两端入口择路；NPC 在楼梯上先撤向远离威胁的一端。
- 尚无自动开门、破门、翻窗及群体避让；装饰物未参与 AI 遮挡。详见 [3D AI 感知与导航](docs/AI_SPATIAL_PERCEPTION.md)。当前验证包含下述自动回归与听觉 CPU 样本，尚未完成全部 AI 行为的人工游玩验收。

### 3D 听觉

- 僵尸和 NPC 共用空间听觉：声音保存发出时的位置与楼梯高度，以三维距离和墙、门窗、楼板、屋顶、楼梯结构计算衰减。开关门窗立即改变传播，不依赖摄像机或已加载的渲染块。
- 玩家动作使用统一声音配置：步行 8、冲刺 18、球棒挥空 12、球棒命中 20、搜刮 5、开门 6、开窗 8 个世界单位；僵尸与 NPC 的近战分别为 9 和 8。传播强度随距离和结构损耗线性衰减；僵尸在收到至少 0.55 强度的声音后调查该位置，新声音会替换正在调查的旧位置，只有途中视觉发现目标才转为追击。NPC 对普通声音转向，对同层打斗等危险声音短暂避让，不通过声音获得发声者身份或持续位置。
- 暂停、休眠僵尸和自身发声不会产生错误反应；听觉记忆与切换锁使用游戏时间并保存，兼容缺少新增字段的 v11 及更早旧档。
- 当前采用直线穿透衰减，尚无绕门口的绕射路径、反射、混响、玩家音频播放或听力特质加成。运行时追加 `-- --debug-hearing` 可输出实际接收强度及障碍明细。传播参数与验证范围见 [3D AI 感知与导航](docs/AI_SPATIAL_PERCEPTION.md#听觉)。
- 2026-10-03 无界面回归通过 506 项检查；听觉密集 CPU 样本（128 个听者、720 段墙、三层）每事件中位约 9.8 毫秒、P95 约 10.2 毫秒。这是同步听觉查询测量，不代表完整帧时间或大地图模拟性能。

### 世界、地图与可见性

- 由 `MapDefinition` 资源驱动地图数据，包含地形绘制、道路、建筑模板/实例、楼层、墙边、楼梯、区域和装饰物等数据结构。
- 当前 64×64 示例地图包含两栋两层住宅和一栋三层杂货店。室内楼层有独立布局、墙体与物资；屋顶不可行走。
- 建筑的墙体、屋顶及上层楼板保留实体显示，进入建筑不剖切、不淡出。墙体和关闭的门窗占位模型填满层高，避免旧俯视表现的顶部缝隙。
- 鼠标在游戏中自动捕获；打开物品栏、人物面板或帮助时释放鼠标并阻止移动／攻击。关闭面板后恢复观察，窗口失焦时释放鼠标。
- 取消玩家视野锥、近身可见圆、感知距离驱动的隐藏、探索记录和地面迷雾。所有区域、物资与角色都可正常渲染，由摄像机视锥、墙体及楼板的深度遮挡决定画面；无需先探索。僵尸感知、攻击、碰撞和交互仍受各自的玩法距离与墙体规则约束。
- 渲染远裁面默认 64 个世界单位，与角色感知属性无关。加载半径覆盖透视画面最远角点，并额外预加载一圈；转身不触发重新加载。日夜光照继续正常变化。
- 树木、路牌保持不透明；第三人称显示完整的 Human 玩家与 NPC 模型，僵尸使用 Mixamo Zombie 模型。
- 静态世界采用 16×16 水平分块，每块包含全部楼层，按材质合并地面、墙、屋顶、楼梯和装饰物。长墙与屋顶跨块拆分；移动加载按约 2 毫秒预算跨帧构建，完成后整体显示，远处最多保留 12 个额外缓存块。门窗开关只更新独立网格。F10 可查看流送计数。地图和导航数据仍常驻；僵尸活动半径独立为 24 单位。

### 玩家、生存与战斗

- 玩家可移动、冲刺、瞄准、近战攻击，并具有耐力、饥饿、口渴、疲劳和负重影响；正常移动不消耗耐力且可恢复，只有冲刺和攻击消耗耐力。
- 玩家近战接触距离增至徒手 2.0、持械 2.4 世界单位，使用随水平朝向和俯仰转动的三维攻击范围（半角 24°），优先选择靠近准星的目标。僵尸与 NPC 共用方向、身体接触和三维遮挡规则，距离分别为 1.2、1.8；墙、门窗、楼板、屋顶及楼梯结构仍会阻挡攻击。当前是单次单目标近战判定，已支持十部位命中与僵尸头部双倍伤害，尚无逐帧武器轨迹碰撞。
- 玩家模型按上下半身分层播放第三人称动作，并在受伤时闪红。锤子和可开关设备使用专用占位形状，其余手持物使用通用占位物；双手槽物品也会显示并跟随上半身动画手腕。服装有状态与防护效果，尚未制作匹配此骨架的袖口、手套和衣物外观。
- 第三人称相机的跟随原点保持精确眼高，并按地图几何缩短，避免镜头穿墙、楼板或屋顶。
- 僵尸会感知并追击玩家、沿楼梯移动、发动攻击；玩家攻击有命中与伤害逻辑，僵尸显示血条。
- 僵尸初始化按地图各楼层热力加权分布，总量由独立人口档位决定（默认 Normal：7–10）；死亡后不刷新。空闲僵尸每隔 20–45 个游戏秒，会在 4–10 米内选择一处可达位置游荡，并稍微偏向高热力区域；声音、视线和区域迁徙会立即中断游荡。档位、实际种群数量和游荡进度随存档保存，存活僵尸继续使用原迁徙系统。
- 人物状态面板（C）显示头、躯干、四肢等身体部位、伤病、穿戴保护和保暖状态，并提供伤病处理入口。
- 伤病包含流血、伤口感染、骨折、烧伤、疼痛与愈合；僵尸咬伤/抓伤可能造成潜伏病毒感染。病毒状态与普通伤口感染分开处理。
- 体温、保暖、受伤和情绪会影响生存表现；疲劳不足时不能正常冲刺。床边休息会推进世界时间，附近危险会打断休息。
- 角色职业、技能与特质数据/进度系统已存在，但完整角色创建入口目前关闭；未实现的特质效果不应视为已支持。

### 物品、容器与交互

- 物品栏使用体积容量和负重计算，支持可装备背包、嵌套容器、装备栏、手持槽、服装槽及逐件转移。
- 玩家默认没有背包；装备背包后才显示对应容器标签。服装标签展示已穿衣物与背包，身体部位不是物品容器。单物品不显示无意义的堆叠下拉菜单；容器在物品栏右侧使用标签切换。
- 搜索、转移、使用、穿脱等操作有耗时；移动、瞄准、攻击等动作可打断。搜索进度可以保留并恢复。
- 容器首次搜索使用各自的 `ContainerData.search_duration_game_seconds`，配置入口为 `InteractionSystem.CONTAINER_SEARCH_SECONDS`（正常速度下的基础现实秒数，初始化时转换为游戏时间）。当前厨房柜 2 秒、客厅柜／邻居柜／杂货架／食品柜 3 秒、卧室斗柜／背包箱 4 秒、衣柜／一楼库房 5 秒、补给箱／顶楼物资 6 秒；角色状态影响效率，暂停冻结、3 倍速加快搜索。准星提示显示剩余时间和进度。
- 搜索期间容器保持关闭，内容不进入“周围物品”；完成后只打开容器，不自动搬运。中断后对准同一容器按 E 续搜；已搜索容器重新打开无需等待，脚边散落物也无需搜索。每个容器的时长、进度与搜索完成状态随存档保存，缺少时长字段的旧档按原 360 游戏秒时长保留进度比例。2026-10-04 全套回归通过 605 项检查。
- E 键按准星选择门窗、容器和床，保留距离、楼层和房间可达规则；每次只开关当前指向的容器。关闭物品栏后，再次对准柜子按 E 可关闭柜子。
- 五个白模柜子已移到住宅室内墙边，分别作为厨房柜、客厅柜、卧室斗柜、衣柜和邻居储物柜。灰色表示关闭，绿色表示打开；目前用颜色表示状态，尚无柜门动画。
- “周围物品”只聚合脚边 0.65 单位内散落物及 1.2 单位内已打开、同层同房间且无遮挡的容器。关闭、离开或隔墙后，原先选中的柜子也不能继续查看或取物。
- 柜体使用统一的 0.5×1.0×0.5 世界单位实体范围，参与玩家／僵尸／NPC 碰撞、寻路净空和三维视线／攻击遮挡；NPC 取物目标位于柜体外。柜子不会因为打开而失去碰撞。
- 开关状态随存档保存；独立的家具布局版本在内存中迁移旧档，将与新增柜体重叠的角色或地面物品移至附近合法位置，缺少开关字段的旧柜子默认关闭。已检查关闭／打开状态截图。
- 测试街区提供背包/搜刮箱、衣物与修理材料、手持设备及伤病验证点。
- 衣物按身体区域提供保护与耐久，支持内外层搭配、保暖、损坏和修理；目前保暖已接入角色体温逻辑。只有外套拥有角色模型上的程序化显示原型。

### NPC、保存与开发工具

- 当前有一名简化幸存者 NPC，可探索已知容器、获取并使用有限物资、休息和避开僵尸；遭遇近身威胁时会转向反击，僵尸也能伤害 NPC。NPC 有生命值和攻击冷却，死亡后停止行为并隐藏，暂未制作尸体和尸体搜刮。这不是完整社交或群体生存系统。
- F5/F9 使用单个本地快速存档槽。当前格式为 v12，记录玩家状态、物品与容器、搜索进度、门窗、NPC、僵尸部位健康及其感知和游荡状态，支持迁移 v3–v11 存档。探索记录不再写入；读取旧档只在内存副本上迁移，后续默认保存到独立的 v12 路径，旧文件保留。存档仍与地图身份绑定。
- 存档新增可选俯仰角字段，读档同时恢复观察方向与攻击方向；缺少字段的旧档使用水平视角，非有限值、错误类型及超出 ±85° 的数据会在恢复前被拒绝。
- NPC 生命值、攻击冷却与 AI 攻击俯仰也随存档保存，缺少这些可选字段的旧档采用兼容默认值。
- 项目启用了 `addons/native_map_authoring` Godot 编辑器插件，支持地形矩形、独立道路、多层地面、墙/静态门窗、直楼梯、房屋模板旋转镜像、热力编辑、尺寸裁切与确认撤销，可保存原生资源并通过主场景试玩。详见 [地图编辑器指南](docs/MAP_EDITOR_GUIDE.md)。
- 地图数据校验器与地图模组清单/注册数据结构已存在；完整的模组发现、装载和创作工作流仍需继续建设。

### 最近一次提交后的地图系统更新

自 `c8bcc79` 之后，地图从主要依赖示例建筑/区域数据扩展为可直接创作和运行的分层资源：

- 新增原生地图编辑器画布与操作组件，支持新建不同尺寸的草地地图、地形矩形填充、整数宽度道路笔刷、楼层选择、相邻楼层参考、缩放和平移，并可查看 3D 静态预览。
- 地形、道路和室内地面采用独立层。道路笔刷在水岸截断；道路或建筑占用的地面不能直接改成水面；扩缩地图、覆盖已有内容和模板盖房都通过确认与撤销处理。
- 可编辑多层室内地面及沿格边放置的墙、静态门窗和直线楼梯。楼梯连续连接相邻楼层，并以可撤销的开洞遮罩移除上层对应楼板；屋顶可独立开关。
- 可框选保存包含楼层、墙段、楼梯、屋顶状态及室内热力的房屋模板，支持旋转、镜像、重复放置、复制、移动和整栋删除/替换。
- 新增 0–1 的分层僵尸热力图。所有可行走楼层共用同一加权生成池；人口总量使用 Very Few 至 Extremely Many 六档独立设定，默认 Normal，人口档位与实际数量写入存档。Orangeville 旧区域压力已迁入对应的地图热力；区域邻接和迁徙仍由原迁徙系统使用。
- 主场景可通过地图资源参数运行已保存的自制地图。非示例地图不会生成 Orangeville 专用测试容器，NPC 的临时住所会采用自制地图出生点。
- 地图验证器覆盖新楼层、热力、道路和模板楼梯数据；存档只对已核验的 Orangeville 旧版地图身份提供迁移兼容，不会忽略其他地图的内容变化。
- 优化了导航邻接构建的支撑检测；第三人称运行流程不使用玩家视野轮廓计算、探索栅格或迷雾纹理上传。

门窗已有开关状态、碰撞／寻路阻挡与存档；当前仍使用占位网格。编辑器拖拽体验的人工验收、自动房间识别和完整大地图模拟压力测试仍属后续工作。完整控件说明见 [地图编辑器指南](docs/MAP_EDITOR_GUIDE.md)。

## 当前边界与已知不足

- 这是小型灰盒 MVP：地图内容、物资种类、NPC 数量、僵尸行为和角色动画都有限，不能代表最终规模或美术质量。
- 第三人称身体来自 Player 骨骼模型，手持物仍是程序化灰盒并跟随动画手腕。完整身体已播放移动、持械和攻击动作；相机已处理地图几何遮挡，尚无脚部落地 IK、枪械瞄准或肩部偏好切换。可开关设备显示开关外观，但尚未提供实际手电照明。
- 玩家、NPC 与僵尸均已使用 Mixamo 骨骼模型。身体判定采用独立的简化部位框，不受渲染动画影响；尚无布娃娃、肢解或完整可动画服装资产流程。
- 角色创建界面暂时隐藏。职业/特质数据存在，但界面、规则覆盖和效果接入需要在后续统一完成。
- 地图编辑器已有多层地面、墙段、模板、楼梯、屋顶、道路与热力工作流；自动房间识别、可视化容器/物件放置和出生点编辑仍未完成。
- 静态渲染已用 512×64、896 段墙和 896 棵树的合成场景测试跨块加载；这不代表完整大地图模拟验收。导航图仍整图构建，启动和模拟规模仍需单独优化。构建预算为软上限，单次网格提交可能略超时；进入游戏和读档会同步准备所需地块。
- 不支持跳窗、坠落、电梯、结构破坏、完整社交、多人游戏或最终内容规模。
- `docs/` 中部分早期设计文档尚未随代码同步；遇到与运行行为不一致时，以当前代码和本 README 的“当前版本/边界”说明为准，并应在后续文档整理中校准这些资料。

## 后续设计方向

建议按下面顺序推进。地图编辑、基础导航和第三人称分块渲染已有基础，后续工作聚焦在规则一致性、可扩展性和玩法闭环：

1. **完善第三人称表现。** 在现有三维近战、视线交互、相机碰撞和骨骼手持物基础上制作正式手持物与动画，并提供肩部偏好。玩家渲染不再恢复探索迷雾或视野半径隐藏。
2. **完善门窗和房间的表现。** 门窗开关、碰撞与保存已接入；后续补正式模型、动画和房间编辑工具。
3. **以测量结果决定地图扩展方式。** 继续分别测量分块构建、整图导航、实体模拟和内存；渲染流送不等于模拟及导航已卸载。
4. **打磨一段可重复体验的生存遭遇。** 将现有搜刮、负重选择、战斗/逃跑、伤病处理、休息和保存组织成清晰目标，并把测试物资与标记调整为有意图的关卡配置。理由：主要系统已能独立运行，下一步应检查它们组合时的节奏、提示和难度。
5. **让角色创建选项对应实际玩法。** 逐项核实职业、技能和特质的规则及存档，再接回目前隐藏的角色创建入口。理由：数据框架已存在，但尚未完成的效果若暴露给玩家，会造成选择与实际表现不符。
6. **在取得角色模型后建立服装资产流程。** 验证骨骼与动画接口，再制作各装备槽的可组合外观，覆盖走路、攻击、受击及内外层遮挡。理由：当前只有外套程序化显示原型，其余服装逻辑尚未对应到正式模型资产。
7. **完成前述性能基线后扩大世界模拟。** 用更大地图验证远近僵尸模拟、NPC 生存、导航和流送，并为这些系统设定帧时间与内存预算。理由：现有区块渲染和局部 AI 降频已提供基础，但大型地图下的整体行为还未验证。

## 地图编辑器入口

项目已在 `project.godot` 启用 `Native Map Authoring` 插件。打开右侧 **Map Authoring**，点 **Open demo** 或 **New**，选楼层与工具进行编辑；滚轮缩放，中键平移。**Save as** 另存副本，**Validate** 校验，**Play saved map** 试玩当前已保存地图。完整操作与限制见 [地图编辑器指南](docs/MAP_EDITOR_GUIDE.md)。

## 存档位置

存档使用 `user://afterlight_mvp_v12.save`，实际位置由 Godot 的用户数据目录决定。F5 保存，F9 读档；没有 v12 槽时依次查找旧 v11–v3 槽。旧档迁移不会改写源文件，存档只适用于匹配的地图身份。
